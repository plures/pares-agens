Procedure Authoring

Extend Pares Agens with custom behaviors by writing typed Rust procedures. Procedures are first-class event handlers that plug into the reactive event loop.

Concepts

Events

Everything in Pares Agens is driven by events. An event carries a typed payload and is dispatched by the executor to all registered handlers:

  • Event::Message — an inbound chat message from any channel
  • Event::ModelResponse — a completed model response
  • Event::Timer — a periodic timer tick
  • Event::StateChange — an arbitrary key/value state update

Procedures

A procedure is an async handler that receives an event context and returns a Vec<Event> of follow-up events to inject back into the loop. Built-in procedures include OnMessage, AutoRecall, and AutoCapture.

Your first procedure

Create a new crate or add to an existing one:

# in Cargo.toml
[dependencies]
pares-core = { git = "https://github.com/plures/pares-agens" }

Implement the EventHandler trait:

use pares_core::{Event, EventContext, EventHandler};
use async_trait::async_trait;

pub struct GreetHandler;

#[async_trait]
impl EventHandler for GreetHandler {
    fn name(&self) -> &str {
        "greet"
    }

    async fn execute(&self, ctx: &EventContext) -> Vec<Event> {
        let Event::Message(msg) = &ctx.event else {
            return vec![];
        };

        if msg.text.to_lowercase().contains("hello") {
            return vec![Event::send_reply("Hey there! 👋")];
        }

        vec![]
    }
}
📌 Key rule Handlers must be pure with respect to side effects on the event loop. All follow-up work is expressed as returned events, never by directly calling other handlers.

Register your procedure

Register the handler when building the executor:

use pares_core::Executor;

let executor = Executor::builder()
    .handler(GreetHandler)
    .handler(OnMessage::new(model_client, memory_client, tool_dispatcher))
    .build();

executor.run().await?;

Working with memory

Inject a MemoryClient to read from and write to pluresLM:

use pares_core::memory::MemoryClient;

pub struct SummaryHandler {
    memory: Arc<dyn MemoryClient>,
}

#[async_trait]
impl EventHandler for SummaryHandler {
    fn name(&self) -> &str { "summarise" }

    async fn execute(&self, ctx: &EventContext) -> Vec<Event> {
        let Event::Message(msg) = &ctx.event else { return vec![]; };

        // Recall existing memories
        let memories = self.memory.recall(&msg.text, 5);

        // Emit a model call with context injected
        vec![todo!("construct the appropriate Event variant with `memories` as context")]
    }
}
vec![Event::model_call_with_context(msg.text.clone(), memories)] } }

Timer-based procedures

Register a periodic timer to drive scheduled behaviour:

use pares_core::handlers::OnTimer;
use std::time::Duration;

// Fires every 60 seconds
let timer = OnTimer::new(Duration::from_secs(60), |_ctx| async {
    println!("tick");
    vec![] // return follow-up events if needed
});

executor.register_handler(timer);

State-change watchers

React to arbitrary key/value state changes published anywhere in the loop:

use pares_core::handlers::OnStateChange;

let watcher = OnStateChange::new("battery_level", |ctx| async move {
    let level: u8 = ctx.value().unwrap_or(100);
    if level < 20 {
        return vec![Event::send_reply("⚠️ Battery low!")];
    }
    vec![]
});

executor.register_handler(watcher);

Testing your procedure

All dependencies are trait objects, so testing is straightforward with mock implementations:

#[cfg(test)]
mod tests {
    use super::*;
    use pares_core::testing::{MockMemoryClient, test_context};

    #[tokio::test]
    async fn greets_on_hello() {
        let handler = GreetHandler;
        let ctx = test_context(Event::message("hello world"));
        let events = handler.execute(&ctx).await;

        assert_eq!(events.len(), 1);
        assert!(matches!(events[0], Event::Reply(_)));
    }
}
✅ Tip Run cargo test --workspace to validate all procedures including your custom ones.
