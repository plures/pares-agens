# IntelligentContext — importance-scored message dropping (milestones)

Epic: Headroom — final dev item. Lever: **compaction-EVENT minimization** (distinct from
footprint/byte reduction which is `headroom_bridge::compress_messages`).

## STAGE 1 — ANALYZE  ✅ (findings below)

### Where conversation/context assembly happens
- `crates/core/src/agent.rs`
  - `conversation_history: Arc<Mutex<HashMap<String, Vec<ChatMessage>>>>` (line ~155)
    — the canonical in-memory history, keyed by channel/session label.
  - `load_history(channel)` (~line 1523) hydrates from PluresDB turn store and returns the
    **LLM-window** view.
  - `persist_turn(...)` (~line 1575) appends new messages then re-compacts the cached history.
  - Both call `Self::trim_to_token_budget(&messages)`.

### Where oldest-first truncation currently occurs  ← THE SEAM
- `Agent::trim_to_token_budget(messages: &[ChatMessage]) -> Vec<ChatMessage>` (~line 1616).
  - Budget: `MAX_HISTORY_TOKENS = 100_000`; reserves `SUMMARY_TOKEN_BUDGET = 2_000`.
  - Algorithm TODAY: iterate `messages.iter().enumerate().rev()`, keep the most-recent
    contiguous suffix that fits; everything **before** `keep_from` is dropped into ONE
    `[Compacted context]` system summary via `build_compacted_summary`.
  - This is **blunt oldest-first**: a high-signal early "the codename is FALCON" / an error /
    a decision gets dropped purely because it is old, even if a low-value "ok"/"thanks" turn
    sits newer and survives.

### The real seam to insert importance scoring
- Replace the body of `trim_to_token_budget` selection with an **importance-scored** selection:
  score every message, then fill the budget by DESCENDING importance (never dropping the
  most-recent turn, never orphaning a tool result from its assistant tool_call), and emit the
  KEPT set in **original chronological order**. Dropped (lowest-value) messages still go into
  the compacted summary. Fewer high-signal drops ⇒ smaller/rarer compaction summaries ⇒ the
  lever's goal.

### Types (critical — two ChatMessage types exist)
- `agent.rs` uses **`pares_radix_core::model::ChatMessage`**: `content: String`, `role: String`
  (proven by `m.role == "user"` and `ChatMessage::system(String)`), plus `tool_call_id`,
  `tool_calls`.
- `crates/models/src/types.rs::ChatMessage` is a DIFFERENT type (`content: Option<String>`,
  `role: Role` enum) — NOT used at this seam. Do not confuse them.

### Embeddings availability at this seam
- `trim_to_token_budget` is a **sync static fn** with no `&self`, no ActionHandler, no embedder.
- Embeddings are `#[cfg(feature = "embeddings")]` (bge-small-en-v1.5 via `pluresdb::FastEmbedder`)
  and only reachable through `HeadroomActionHandler::call("compute_embedding")`. `compress_messages`
  explicitly never calls it (hot-path cost).
- ⇒ Semantic-centrality via embeddings is a **capability-gated** enhancement. The **default active
  path is a real deterministic heuristic** (recency + role + content-signal + explicit-keep). This
  is NOT a stub — it is a fully-working scorer; embeddings only ADD structural-centrality signal
  when a caller supplies precomputed per-message embeddings.

## STAGE 2 — DESIGN  ✅

### Scoring function (implemented in `headroom::score_message_importance`)
Composite in [0,1], higher = keep. Weights sum to 1.0 (recency+role+signal); the semantic
term is an ADDITIVE capability-gated bonus (max +0.15) folded in and re-clamped, so absence
of embeddings never inflates or deflates the base ranking — it just omits one signal.

| Signal | Weight | Definition |
|---|---|---|
| recency | 0.40 | `rank/(n-1)` where rank 0=oldest, n-1=newest ⇒ newest=1.0. Linear. |
| role | 0.25 | user=1.0, assistant=0.75, tool=0.55, system=0.35 (base); a system msg that `looks_like_error` OR carries an explicit-keep marker is lifted to 0.9 (decisions/compacted-context). |
| content-signal | 0.35 | max of: error=1.0 (`looks_like_error`), explicit-keep-marker=0.9, has-tool-calls=0.7, code/log-density=0.5, else length-normalized 0..0.4. |
| semantic-centrality | +0.15 bonus | mean cosine of this msg's embedding vs all others (capability-gated: only when caller passes `Some(embeddings)`; else omitted). |

**Explicit-keep markers** (case-insensitive substring, high-signal turns humans must not lose):
`remember`, `important`, `decision`, `decided`, `codename`, `do not`, `never`, `always`,
`api key`, `token`, `password`, `secret`, `todo`, `fixme`, `error`, `panic`, `failed`.

### Hard-keep invariants (structural, applied AFTER scoring, BEFORE budget fill)
1. The **last** message (most recent turn) is always kept — force score to +∞ rank.
2. A `role=tool` result is kept **iff** the assistant message bearing its parent `tool_call_id`
   is kept — never orphan a tool result (breaks the model's function-calling contract).
   Conversely if a tool result is force-kept, its parent assistant msg is force-kept.
3. Output ordering is **original chronological**, never score order.

### Selection algorithm (`select_by_importance`)
1. Score all messages.
2. Apply hard-keep #1 (last msg) → mandatory set.
3. Greedily add messages by DESCENDING score while `sum(cl100k tokens) <= budget`.
4. Resolve tool/assistant pairing (invariant #2) — pulling in a partner may evict the current
   lowest-scored optional member if it would bust budget (partner takes priority for integrity).
5. Emit kept set in original order; the complement (dropped, lowest-value) feeds the existing
   `build_compacted_summary`.

### Why this reduces compaction EVENTS
Blunt oldest-first drops a contiguous prefix regardless of value; a single high-signal early
fact forces re-surfacing (re-injection, re-summary) on later turns → more compaction churn.
Importance-scored dropping keeps that fact resident, so the compacted summary is smaller and
regenerated less often. Same 100K budget, higher-value residents.

### `.px`?
The headroom `.px` procedures already model a block-scoring pipeline (`compute_composite`,
`compute_recency_score`, `compute_source_score`), but that pipeline scores *content blocks* for
compression, not *conversation messages* for retention, and it is not wired to `trim_to_token_budget`
(sync static fn, no executor). The retention scorer lives as native Rust at the seam where it is
called. It mirrors the `.px` composite shape (recency+role/source+signal) so the model stays
consistent. No new `.px` needed for this lever; documented here + in code doc-comments.

### Scoring function ACTUALLY implemented
composite = clamp( 0.40*recency + 0.25*role + 0.35*signal + semantic_bonus )
- recency = idx/(n-1) (newest=1.0)
- role = user1.0/assistant0.75/tool0.55/system0.35, system lifted to 0.9 if error/keep-marker
- signal = error1.0 / keep-marker0.9 / has-tool-calls0.7 / code|log0.5 / len-norm..0.4
- semantic_bonus = 0.15 * mean-cosine-centrality, ONLY when caller supplies embeddings
  (capability-gated; 0.0 otherwise — honest, not a fake)

### Honest capability-gated degradation
Embeddings path is REAL but gated: `MessageMeta.embedding: Option<&[f32]>`. At the
`agent.rs::trim_to_token_budget` seam (sync static fn, no px executor / no embedder
handle) we pass `embedding: None` → the deterministic recency+role+signal heuristic runs
(fully functional). When a caller precomputes bge-small-en-v1.5 embeddings and passes them,
the semantic-centrality term activates. No feature is advertised that isn't wired.
